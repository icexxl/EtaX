# EtaX 后台副屏

免 Root 副屏基于 Agent-VScreen 的 Shizuku UserService。启动 Shizuku 并授权 EtaX 后，在设置的「免 Root 虚拟屏」中连接副屏。EtaX 不再保存无线 ADB 连接或要求输入配对码。Shizuku 自身如何启动由其管理器负责。

## 生命周期

- Shizuku 独立服务持有副屏；EtaX 持有 ImageReader、截图和预览。
- 任务结束、关闭结果卡片、EtaX 服务销毁都只会**分离**预览：先把守护进程的 Surface 置空（park），
  再关闭本地 ImageReader，副屏上的应用保持运行；再次连接时通过 LIST / SET_SURFACE 重新接入，
  并按副屏名挑选自己的屏（多块无名副屏时拒绝猜测）。
- 只有设置页的「关闭副屏」才会释放守护进程中的副屏。
- 服务中超过 20 分钟没有被接入或操作的副屏会自动回收；EtaX 接入时每 10 秒续期。
- Shizuku 服务被停止、权限撤销或手机重启后，不保证副屏继续存活。需要先重新启动并授权 Shizuku。
- 启动应用由守护进程直接执行 `am start`（它本身就是 shell 身份），不再依赖 Shizuku 的隐藏进程 API；
  启动后核对目标包确实在该屏，失败不在主屏继续操作。
- 输入显式指定副屏 ID；服务只接受其拥有的屏。
- 用户临时接管只按已记录任务 ID 返回副屏。EtaX 完整进程重启会丢失临时接管记录，此时拒绝猜测用户主屏任务。

已有 Root/LSPosed 建屏路径保留为未启用 Shizuku 时的兼容后端；普通主屏与其他 Root 工具不依赖 Shizuku。界面节点与文本编辑仍使用 EtaX 已有无障碍服务。

## 真机验收

1. 未授权、Shizuku 未启动时，状态和失败信息准确。
2. 授权后建屏并启动测试应用，观察主屏不被抢占。
3. 副屏点击、长按、滑动、返回键均只作用于副屏。
4. App 进程退出后重新打开并连接，确认同一副屏可重新接入。
5. 临时移交与返回操作的是确切任务；关闭副屏后不再保留后台副屏。
6. 断 Wi-Fi、锁屏和权限撤销后观察状态，不把未验证的后台存活当成保证。
