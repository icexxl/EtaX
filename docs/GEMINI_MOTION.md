# Gemini 回复动效拆解（EtaX 实现依据）

样本：`VID_20261109_221005.mp4`（40.8s，566×1300）与 APKM `com.google.android.apps.bard 1.0.995038376`。

## APK 结论

Gemini 安卓端不是原生渲染聊天界面。DEX 里只有 shell：`BardEntryPointActivity`，字符串指向
`https://bard.google.com/android?source=bardshell`。也就是说**回复时的渐变和文字动画由网页前端
（CSS/JS）绘制在 WebView 里，APK 内没有对应的原生动画代码**，无法从 APK 直接读出参数。

于是改为对录屏做逐帧测量。

## 测量结果

| 项目 | 实测值 |
|---|---|
| 同一时刻左右色相差 | 24°–52°（均值约 35°） |
| 色相一圈周期 | **8 秒**，且非匀速：首尾速度≈0，中段 70–90°/s |
| 色相速度曲线 | 近似余弦缓动，0–1s≈0、2s≈20、3s≈55、4s≈70、5s≈50、6s≈90、7s≈30°/s |
| 空间刚性位移 | ≈0 px（1/3/5/10 帧间隔的相位相关都锁定在 0） |
| 纵向分布 | 顶部最亮；饱和度约 0.85；亮度 0.10→0.44 处由 0.51 降到 0.11，约 0.58 处归零 |
| 左右色相差是否随速度塌缩 | **会**：中段 18–26°，缓动平台段收敛到 1–7° |
| 出现/停止 | 整幅同时显隐，没有横扫式收放 |

关键推论：**颜色场是「横向色相坡道 + 整体匀速色相旋转」**。因为坡道存在，色相旋转时
同一种颜色的等值线会横向移动，观感上就是颜色从左向右流动；这正是「流动感」的来源，
而不是真的有一团色块在平移。整屏同色再旋转，就会退化成整片闪变。

## EtaX 对应实现

`AuroraBackground.kt`：

- `LAP_SECONDS = 8f`，`lapEase()` 用 smoothstep 把线性进度压成 S 曲线。
- `COLUMN_LAG_SECONDS = 0.4f`：右侧比左侧晚 0.4 秒起步，各列走同一条 S 曲线的不同位置，
  于是中段呈现一道色带，平台段几乎整屏同色——与实测的 1–7°/18–26° 一致。
- 显隐只看统一的包络时间，颜色相位只影响色相，不影响出现/停止。
- 竖向衰减沿用原有配色与形状，与实测剖面一致（约 0.55–0.60 屏高归零）。

文字：流式分块独立淡入约 260ms，多块重叠，尾部不提前变亮；与录屏中「前亮后暗」的
渐变尾巴一致。历史消息不重播动画。
